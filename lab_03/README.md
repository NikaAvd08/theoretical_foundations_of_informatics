## Краткое описание задачи
Разработка консольного приложения для автоматизации обработки заявок сервисного центра. Программа моделирует работу центра, распределяя поступающие заявки по двум очередям (обычные и срочные), ведёт историю выполненных заказов и поддерживает отмену операций. 

Главное условие работы — **полный запрет на использование встроенных коллекций Python** (`list`, `dict`, `set`, `tuple`) для хранения и обработки данных. Все линейные и нелинейные структуры данных реализованы вручную на основе узловых ссылочных моделей.

## Формат входного файла
Данные считываются из текстового файла `input.txt`. Каждая непустая строка представляет собой отдельную запись заявки без заголовков полей.  
Формат строки:
```text
номер;клиент;тип;категория;приоритет
```

### Примеры записей:
* **Корректная запись:**
  ```text
  2002;Петрова Анна;консультация;приём;срочная
  ```
* **Некорректная запись (отсутствует обязательное поле категории):**
  ```text
  2007;Васильев Игорь;ремонт;;срочная
  ```

1. Убедитесь, что файлы `main.py`, `data_structures.py` и текстовый файл `input.txt` находятся в одной рабочей директории (папке `lab_03/`).

## Описание структуры программы
Программа разделена на два логических модуля:
1. **`data_structures.py`** — низкоуровневый модуль, содержащий классы ручных ссылочных структур данных (`Node`, `LinkedList`, `Stack`, `Queue`, `HashTable`) и их внутренние методы манипуляции узлами.
2. **`main.py`** — высокоуровневый модуль, содержащий основу программы (валидация файла, функции обслуживания и отмены, расчет статистики, рекурсивные алгоритмы, автоматические тесты и организация консольного интерфейса).

## Перечень реализованных структур данных и их операций
Все операции спроектированы с учетом теоретических асимптотических оценок сложности ($O(1)$ для базовых операций, $O(n)$ для поиска и удаления).

* **`Node`** — базовый кирпичик ссылочной модели, хранящий значение (`value`) и ссылку на следующий узел (`next`).
* **`LinkedList` (Связный список)** — используется для хранения истории обслуживания.
  * `append(value)` — добавление в конец за $O(1)$ с использованием указателя на хвост (`tail`).
  * `reverse()` — инвертирование списка за $O(n)$ путем изменения направления ссылок `next`.
* **`Stack` (Стек на узлах)** — используется для отката действий (LIFO).
  * `push(value)` — добавление на вершину за $O(1)$.
  * `pop()` — удаление и возврат с вершины за $O(1)$ (выбрасывает `IndexError`, если пуст).
* **`Queue` (Очередь на узлах)** — моделирует очереди ожидания (FIFO).
  * `enqueue(value)` — добавление в хвост за $O(1)$.
  * `dequeue()` — извлечение из головы за $O(1)$ (выбрасывает `IndexError`, если пуста).
  * `remove_by_id(req_id)` — удаление узла из произвольного места очереди за $O(n)$ путем переброски указателей соседей.
* **`HashTable` (Хэш-таблица)** — используется для быстрого поиска и накопления статистики.
  * Реализована на базе фиксированного массива объектов `LinkedList`. 
  * Разрешение коллизий: **метод цепочек**.
  * `put(key, value)` — добавление или обновление за $O(1)$ в среднем.
  * `get(key)` — поиск за $O(1)$ в среднем.
  * `remove(key)` — удаление за $O(1)$ в среднем.

## Пояснение использования ссылочной модели в программе
Программа наглядно демонстрирует фундаментальные правила ссылочной модели данных:
1. **Изоляция данных и передача по ссылке:** Присваивание (`b = a`) в Python связывает несколько имён с одним и тем же объектом в памяти, а не копирует его. Изменения полей внутри функций влияют на исходный объект, что используется при модификации заявок.
2. **Изменение очередей без сдвигов элементов:** Удаление заявки из середины очереди (`remove_by_id`) осуществляется за счёт изменения локальных ссылок `next` у соседних узлов: `prev.next = curr.next`. В отличие от массивов, память не сдвигается, что работает быстрее и эффективнее.
3. **Безопасность обхода цепочки:** При удалении элементов во время обхода связного списка ссылка на следующий узел извлекается *до* модификации текущего узла, чтобы избежать разрыва и потери остатка цепочки.
4. **Неизменяемость ключей:** Ключи в `HashTable` обязательно приводятся к неизменяемому типу (с помощью `frozenset`), так как изменение состояния объекта внутри таблицы приведет к изменению его хэш-значения и безвозвратной потере объекта в бакетах.
5. **Рекурсивный обход:** Так как у связных списков отсутствует индексация, обход истории (`recursive_walk`) и поиск по ней (`recursive_search`) выполняются рекурсивно. Базовым случаем остановки рекурсии является указатель узла на `None`.

## Перечень обработанных ошибок
Программа защищена от аварийного завершения и корректно обрабатывает следующие нештатные ситуации с выводом понятных сообщений пользователю (без пустых блоков `except Exception`):

1. **Отсутствие входного файла** — регистрируется ошибка, программа продолжает работу с пустыми очередями.
2. **Неправильное количество полей в строке файла** — строка пропускается, фиксируется ошибка парсинга.
3. **Неверный формат или знак номера заявки** — проверяется на `isdigit()` и строгое подмножество $> 0$.
4. **Повторяющийся номер заявки** — отслеживается дублирование ID на этапе загрузки с фиксацией коллизии.
5. **Пустое обязательное поле** — проверка на отсутствие данных в полях «клиент» и «категория».
6. **Неизвестный тип заявки** — валидация по эталонному списку `TYPES`.
7. **Неизвестный приоритет** — валидация по эталонному списку `PRIORITIES`.
8. **Обслуживание при пустых очередях** — пункт меню выдает сообщение, не вызывая падения.
9. **Попытка снять заявку с пустого стека** — перехватывается ручное исключение `IndexError`.
10. **Отмена несуществующей заявки** — метод возвращает `False`, выводится уведомление.
11. **Отсутствие результатов поиска** — рекурсивный поиск и хэш-таблица возвращают `None`, обрабатываемый интерфейсом.
12. **Неизвестный пункт меню** — ветка `else` в цикле обрабатывает некорректный ввод пользователя.
